# 承诺型 Lens 准入门

本门只解决一个问题：当前事件是否值得占用一次独立上下文。它不是研究阶段、后台 Router、审批器或第二套权威状态。研究路线仍由 Codex 自主决定。

## 一、先识别可观察事件

只有以下事件进入准入判断：

1. **核心主张冻结**：准备把最终目标值、可行性、优越性、稳健性、机制、外推或现实决策建议写入摘要、结论、最终结果或提交文件。
2. **不变量异常**：复杂或动态方案劣于其嵌套可行基线；概率质量、守恒、量纲、归一化、边界或复现关系出现真实矛盾。
3. **正式交付就绪**：论文、报告或提交包已经生成并可被实际渲染或打开，准备声明 `READY`、可交付或可提交。
4. **上下文切换**：真实跨 Chat、交接或压缩恢复，关键研究语境可能丢失。

普通中间结果、文件写入、工具调用、指标波动、措辞修改、例行复盘和“最好再看一眼”的感觉不进入本门。

## 二、机械检查优先

先重算能够确定性判断的部分：字段、行数、ID、约束、量纲、公式恒等关系、概率质量、上下界、哈希、复现差异、链接、渲染和空值。机械检查已经充分回答问题时，主 Chat 直接修复或缩窄主张，不启动独立审查。

机械检查失败不自动意味着需要新 Chat。只有失败的数学含义、证据边界或模型选择仍需独立语义判断时，才继续准入。

## 三、四个准入条件

除真实上下文切换外，只有以下条件同时满足才接纳独立审查：

- **高影响**：错误会改变模型选择、最终数值、关键结论、现实决策或正式交付可信度；
- **非机械**：单靠确定性检查不能充分裁定主张能支持到什么程度；
- **可改变**：不同上下文有现实可能推翻、缩窄或重定向当前判断，而不只是润色；
- **可有界**：能把审查压缩成一组明确主张、一个决定性问题和最少必要工件，审查者不必重做整题。

任一条件不满足就跳过，并在现有运行或完成报告中写一句理由。

## 四、路由

- 核心主张冻结 → `CLAIM_CHECK.zh-CN.md`
- 已观察到不变量异常 → `ADVERSARIAL_RESEARCHER.zh-CN.md`
- 正式交付已经生成 → `DELIVERY_REVIEW.zh-CN.md`
- 真实跨 Chat 或恢复 → `HANDOFF_RESUME.zh-CN.md`

一次只发送一份 Lens。若多个问题可以由同一组工件和同一个决定性问题审查，应合并成一个主张包。

## 五、审查预算

默认每个持久项目：

- 核心主张审查至多一次；
- 有正式交付物时，交付审查至多一次；
- 不变量异常优先并入核心主张审查；只有继续研究会造成显著浪费且无法机械解释时才立即单独发送。

默认总计不超过两个独立审查上下文。第三次审查必须满足：出现新的实质性数学定义、核心代码、数据来源或交付形态变化；旧审查不能覆盖；信封中明确说明预期改变的判断。错别字、图表配色、文件改名、解释顺序和未改变结论的重跑不构成再次审查。

## 六、审查信封和返回

只在审查被接纳时，复制 `templates/REVIEW_ENVELOPE.zh-CN.md` 到项目现有 `audit/reviews/`。信封只包含：触发事实、精确主张、决定性问题、原始题面条款、最少必要工件、已经执行的机械检查、明确排除项和期望输出。

独立审查者先读原始材料和工件，再接触主 Agent 的解释；只返回首个分歧、通过范围、主张应维持/缩窄/撤回到什么程度和仍不能证明什么。主 Agent 负责修复或缩窄主张。返回结果本身就是审查记录，不再维护 Lens 注册表、审批状态或共享可写记忆。

若宿主不能创建独立 Chat 或 subagent，明确记录能力缺失，并在当前 Chat 使用机械重算与最小反例搜索；不得声称已经完成独立上下文审查。
