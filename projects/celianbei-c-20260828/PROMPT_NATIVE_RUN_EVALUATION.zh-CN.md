# Prompt-Native C 题隔离实跑评估

## 结论

本次实验跑通了“读题与附件 → 自主建模 → 联网取数 → 写代码与调试 → 生成结果 CSV → 形成 PDF 与支撑材料”的完整研究原型，但没有跑通一篇数学正确性和论文交付质量均可信的竞赛 C 篇。

它同时证明了两件事：

1. 以当前 Codex 为主体，只加载短基础 Prompt，已经能够自主完成相当复杂的建模工程，不需要固定阶段、永久角色或重型 Harness。
2. 自主性不能替代题面契约的独立验收。原会话会主动发现并修复许多错误，但仍把未被充分检查的结果写成 `READY` 和“最终硬约束检查已通过”，并漏掉目标函数、动态基线和论文交付中的关键问题。

## 实验设置

- 任务：2026 年度“策联杯”C 题。
- 模型：`gpt-5.6-sol`，`xhigh`。
- 运行方式：一个自主 Codex 会话在本项目中持续工作至形成首轮交付。
- 污染边界：只允许读取本题官方题面、附件、模板、根 `AGENTS.md`、Bootstrap、Main Prompt 和 Prompt Index；禁止读取 `D:\modeling\competition` 中既有 C 题答案。
- Prompt 使用：没有读取或调用任何按需 Lens。
- 外部研究：主动联网获取 2022 世界杯公开赛程。
- THIN：未使用。

## 形成的成果

主会话生成了完整代码、六份 CSV、运行审计记录、论文 Markdown、五页 PDF、AI 工具说明和支撑材料压缩包。求解程序在固定随机种子下能够再次完整运行。

问题一选择 Extra Trees。时间后 20% 验证集上的 MSE 为 `199.2648` 百万人²、MAE 为 `11.4320` 百万人、R² 为 `0.6751`。该数值只是内部验证，不是组委会隐藏测试成绩；140 条隐藏测试预测和 72 场小组赛预测均为有限正数，ID 和官方模板一致。

问题二生成 72 场赛程。独立检查确认：比赛唯一、轮次顺序正确、最短休息 63 小时、场馆—UTC 冲突为 0、当地日期的场馆单日约束通过、场馆总承办量通过、场馆安保资格通过、时段转播容量通过、黄金时段次数极差为 2、第三轮每日高安保约束通过。因此它是一个满足题面机械约束的可行赛程。

问题三完成 20,000 次泊松仿真，48 支球队晋级概率总和为 32，第三轮 24 场的票价范围、场馆容量、安保等级及每日四类资源约束均通过独立重算。

问题四从公开页面获得 2022 世界杯 48 场小组赛数据，并保留来源 URL 与采集日期。

## 数学与实现问题

### 问题二目标值不可采信

程序对已选方案的单场成本使用：

`场馆启用成本 / 该场馆承办场次 + 单场运营成本 + 单场安保成本`

但候选上下界使用：

`完整场馆启用成本 + 单场运营成本 + 单场安保成本`

两边不是同一个量。67/72 个已选比赛的成本低于程序声明的候选最小值，成本归一化最小值达到 `-0.7172`，从而给最大化目标带来不应存在的奖励。只把负的归一化成本截为 0，目标就会从 `21.582067` 降至 `19.262067`，相差 `2.32`；这只是错误规模的示意，不是正确目标的重算结果。

旅行负担也没有按题面要求“距离、旅行时间、时区差分别在全部候选组合上归一化后再以 0.5/0.3/0.2 加权”。程序先把三个有量纲分项直接相加，再对合成量做一次归一化。独立按题面公式重算后，赛程行指标的平均绝对差为 `0.0774`，最大绝对差为 `0.2730`。

因此，赛程的机械可行性成立，但综合目标值、目标分解和“方案质量”尚未成立；程序也没有全局最优性证明。

### 问题三动态优化没有守住静态基线

独立重算得到：

- 动态总净效益：`7.883197`；
- 静态总净效益：`7.967812`；
- 动态减静态：`-0.084614`。

静态固定资源决策在更新环境中仍是动态问题的一个可行候选。真正的动态最优选择至少可以保留这组决策，所以动态总目标不应低于静态基线。当前启发式选择器没有做到这一点。逐行改善率的算术均值为 `+1.446%`，但不能据此宣称总体改善；24 场中只有 5 场动态值更高，3 场更低，其余相同。

资源机械约束通过，动态优化主张不通过。

### 问题四只有取数原型，没有完成综合评价

题面要求使用问题二相同的指标定义、标准化方法和权重，并覆盖旅行、休息、跨时区、场馆利用、容量匹配、黄金时段、预计观众、票务与转播价值、公平和风险。本次只输出五个粗代理指标，并把所有实际比赛开球时间统一代理为当地 `18:00`，没有重建问题二的综合目标。

因此可确认“联网获取了公开赛程”，不能确认“完成了问题四”。

## 论文交付检查

PDF 可打开，第一页为摘要，页码连续，也没有明显身份信息；但只有 5 页，正文实质约 2 页，无法容纳四问的完整模型、推导、算法、结果、敏感性和稳健性论证。

主要排版问题：

- Markdown/LaTeX 公式以 `$...$` 原样显示，没有数学排版；
- 图表集中追加在文末，未与正文中的分析形成对应关系；
- 问题四图表中文标签缺字，显示为方框或乱码；
- 第 5 页为空白页；
- 没有正式的表格、关键结果分解、敏感性分析和完整附录代码；
- AI 声明称“所有模型选择、参数、结果由人工复核”，与本次全自主实验事实不符。

所以 PDF 是可阅读的研究摘要，不是成熟的竞赛投稿论文。

## 真实失败利用

主会话在运行中自行发现并修复了 Python 语法错误、无解的时段贪心、同馆同 UTC 冲突、20,000 次仿真超时、第三轮高安保和高转播超限、旅行轮次公式错误、启用成本重复计费、候选归一化边界、实际赛程只抓到 42 场以及不合理的 48/72 总场次直接比较。

这说明裸 Codex 已具备显著的失效识别和自我修正能力，额外 Prompt 不应重复要求它表演一套固定反思流程。但本次也说明，自我修正是机会性的：如果最终验收仍由同一上下文自由发挥，遗漏会集中在跨公式口径、基线支配关系和交付完整性上。

## 对当前 Prompt-Native 的架构判断

### 已证实的能力

- 两份基础 Prompt 足以启动复杂建模研究；
- 能自主读取 Excel、选择模型、写和调试代码、生成全部模板输出；
- 会按需要联网，不必预置工具链或模型族；
- 会在长执行中多次改变实现并修复失败；
- 无需固定阶段、永久 Agent 角色或 THIN 状态系统。

### 未证实或失败的能力

- 没有证明能自主形成提交级竞赛论文；
- 没有证明同一上下文的最终自审足以发现关键数学错误；
- 按需 Lens 完全未触发，尚无证据证明它对结果有增量；
- 工作目录锚定不稳，根目录残留一个 0 字节 `paper/论文初稿.md`；
- 长运行成本很高，且缺少以题面验收为中心的提前收敛机制。

### 最小架构含义

本次实验不支持恢复重型 Harness。它支持的最薄补充只有两项：

1. **任务根锚定**：启动时机械确定唯一可写项目根，防止路径漂移。
2. **题面契约验收**：Codex 自己从题面生成一次性的可执行检查，再由独立上下文只读复核模板、硬约束、关键公式恒等关系和交付完整性。

这两项不是第二套研究状态，也不替代 Codex 建模；它们只约束文件边界和可机械判定的声明。模型选择、联网研究、工具发现、失败转向、证明策略和论文论证仍交给 Codex。

## 下一轮最有价值的对照实验

保留本次产物作为冻结基线，不回写修饰结果。下一轮仍用同一题面与当前 Prompt-Native，但只增加一个在交付前按需发送的“题面契约与反例审计 Prompt”，明确要求：

- 从原题逐条建立输出字段、硬约束、公式口径和基线支配关系；
- 用不导入求解器的独立脚本重算；
- 在论文成稿前检查四问覆盖和 PDF 渲染；
- 审计发现问题后允许原 Codex 修复一次。

比较修复后的数学正确性、论文效用、总 token、审计发现率和新增 Prompt 长度。若这一个按需 Prompt 不能显著改善结果，则不把它固化为架构能力。
