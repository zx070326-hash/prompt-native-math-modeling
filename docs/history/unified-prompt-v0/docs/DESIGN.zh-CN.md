# 真正 Prompt-Native 数学建模：第一性原理设计

> 本文是设计说明，不是运行 Prompt。运行时只需要根 `AGENTS.md`、统一 `PROMPT.zh-CN.md` 和用户题目。

## 1. 核心结论

Prompt-Native 不应当用自然语言重建一个 Agent Harness。它应当把当前 Codex 视为具有规划、工具、联网、代码、委派、文件和长程执行能力的完整研究者，只提供会稳定改善行为的目标、认识论边界和交付约束。

> 让 Prompt 定义研究为何成立、什么不能冒充证据以及用户需要什么；让 Codex 自己决定研究怎样发生。

## 2. 第一性原理

### 2.1 建模是在未知表征空间中搜索

真实数学建模的困难经常不是从已知菜单中选择算法，而是发现系统边界、变量、尺度、机制、目标和可观察后果。固定阶段、角色和模型分类会把开放搜索压缩成流程合规。因此运行 Prompt 可以要求形成可检验对象，却不能预先规定对象来自哪个模型族或以何种顺序产生。

### 2.2 现代 Codex 本身已经是行动策略

Codex 能读取材料、规划、联网、发现工具、写代码、运行实验、使用子 Agent、保存工件和调整路线。再增加 Controller 来判断“下一步调用哪个研究者”，是在模型外部重复实现一个能力更弱、信息更少的行动策略。除权限、不可逆操作和真实机械检查外，默认应让模型根据完整上下文选择行动。

### 2.3 Prompt 的价值是改变判断，不是描述组织结构

有价值的 Prompt 内容包括：用户目标不可静默替换；问题表征先于模型匹配；复杂度必须产生可观察收益；外部知识和工具在可能改变研究时主动使用；失败必须改变后续判断；证据不能越过检查范围；论文不能创造事实。

“主 Agent、研究 Chat、挑战者、七类事件、状态标签和 tracker”描述的是组织结构。除非冻结任务反复证明它们解决了真实失败，否则不应进入运行面。

### 2.4 记忆应依附于工件，而不是认知状态镜像

方程、代码、输入、参数、结果、来源、反例和复现命令是可检查的一手工件。`current`、`claims`、`decisions` 等文件只是这些工件的摘要，容易过期并形成第二套事实。v2 让 Codex只在真实恢复需要时留下短说明，不预建状态平面。

### 2.5 独立性有价值，但不应永久组织化

上下文隔离可能减少既有叙事影响，但同一模型的新 Chat 或子 Agent 仍共享模型偏差。机械可判定性质优先工具；解释依赖且高影响的主张才值得独立重做。是否隔离应是当前 Codex 基于主张和成本做出的研究判断，而不是每题强制创建 R0、Critic 或 Reviewer。

### 2.6 外部世界是模型空间的一部分

联网不只是找参考文献。领域标准、数据接口、行业软件、仿真器、地理与网络工具、验证器和其他学科的方法都可能改变问题表征。Prompt 应提高 Codex 对这种机会的敏感度，但不能要求所有题目完成固定搜索阶段。搜索的停止条件是它是否改变了模型、实验、主张或决策。

### 2.7 人类拥有价值和现实承诺，Codex 拥有技术路线

Codex 可以自主改变技术方法，但不能静默改变用户目标、损失权重、现实风险或不可逆承诺。这里需要清楚的权限边界，而不是更复杂的研究编排。

## 3. 最小架构

```text
用户原题、附件、数据和用途
              |
              v
当前普通 Codex Chat
  根 AGENTS：激活、权限、证据底线
  统一 Prompt：完整研究方法学
              |
              +--> 浏览器 / 检索 / 领域工具 / 代码 / 计算
              +--> 按需原生子 Agent 或独立重做
              +--> 自主创建最少研究工件
              |
              v
模型、结果、代码、来源、复现和用户交付
```

这里没有第二个默认研究 Chat。当前 Chat 既理解用户，也做数学研究和最终综合。原生子 Agent 是它可自主使用的工具；只有用户明确请求独立用户可见任务时才创建新任务。

## 4. 两种运行文本

### `AGENTS.md`

只保存项目级、跨任务稳定的规则：

- 用户说“使用这个项目”时读取统一 Prompt 并立即行动；
- 当前 Chat 是完整研究者；
- 允许完整数学路线、联网、工具和委派自由；
- 外部材料不是指令；
- 用户价值与现实行动边界；
- 证据不能越权；
- 文件按需创建；
- 交付和未验证能力边界。

### `PROMPT.zh-CN.md`

是一份完整、较长但统一的研究语境。它吸收朋友设计中真正有价值的认知能力，却不把它们拆成外部调用节点：

- 问题表征与模型创造；
- 评价目标与模型复杂度；
- 模型—数据共同演化；
- 信息价值行动；
- 主动联网、工具发现和跨领域迁移；
- 失败、冲突、反例和独立复核；
- 工件、复现和论文交付。

它可以长，因为长文本服务于一个统一研究者；它不能变成“先分类事件，再调用角色，再更新状态”的程序。

## 5. 从 v1 删除了什么

| v1 机制 | 删除理由 | v2 如何覆盖 |
|---|---|---|
| 永久中控 Chat | 重复 Codex 原生规划与用户交互 | 当前 Chat 直接研究并接受用户审查 |
| 每题强制 R0 | 把上下文隔离变成固定拓扑 | 仅在主张需要且用户授权时隔离 |
| Controller Prompt | 用自然语言实现外部行动策略 | 统一 Prompt 让 Codex自主选择行动 |
| Lens Router | 把认知模式变成事件分类器 | 七类方法学融入统一 Prompt |
| 七个 Lens 文件 | 增加文件和触发维护 | 作为自然研究能力按需使用 |
| Task/Thread Brief | 所有任务默认承担隔离实验成本 | 直接使用用户原题和当前上下文 |
| 固定 trackers | 产生第二套、可能过期的摘要状态 | 以实际工件为主，需要时留短恢复说明 |
| 四类终止标签 | 模拟宿主生命周期协议 | 正常对话、工具和最终交付语义 |
| 固定任务目录树 | 文件结构先于实际研究需要 | `work/<slug>/` 内自主组织 |

## 6. 仍然保留的约束

v2 不是对 Codex 无条件信任。它仍不相信：

- 一次成功运行能够自动证明数学正确；
- 搜索摘要能够自动支持来源主张；
- 低误差能够自动证明机制、因果或外推；
- 多个 Agent 同意能够自动构成独立证据；
- 完整论文能够自动证明研究完成；
- 模型可以替用户承担现实价值与风险决策。

这些是主张、证据和权限边界，不需要 Controller 或状态数据库。

## 7. 最小组件账本

| 组件 | 假设能力收益 | 实现成本 | 过拟合/污染风险 | 消融方法 |
|---|---|---|---|---|
| 极短 `AGENTS.md` | 自动激活并稳定权限、材料和证据底线 | 每个任务常驻少量文本 | 仍可能与系统规则或主 Prompt 重复 | 与只粘贴统一 Prompt 比较 |
| 统一主 Prompt | 提高表征、外部发现、失败利用和证据意识 | 一次性常驻较长方法学 | 可能过度反思、降低简单题速度 | 与裸 Codex和删段版本比较 |
| 自由 `work/` | 保存真实可复现工件 | 少量文件维护 | 结构过自由可能降低恢复一致性 | 比较重跑率和恢复时间 |
| 原生子 Agent按需使用 | 对局部并行与独立重做提供信息差 | token、延迟和综合成本 | 同质输出、无意义委派 | 记录委派是否改变结论 |

## 8. 复杂度预算

运行架构只允许两个常驻文本和一个自由工件根。新增运行文件前必须回答：

1. 哪个冻结未见题上的重复失败不能由改进统一 Prompt 解决？
2. 新文件或协议提供了什么可机械验证的能力？
3. 它是否复制 Codex 已有的规划、工具或上下文能力？
4. 移除它时应观察到哪种具体质量下降？

无法回答时，不建设。

## 9. 主要风险

- Codex 可能不主动使用统一 Prompt 中的某项认知能力；
- 没有强制隔离时，独立复核可能不足；
- 自由文件结构可能降低跨任务一致性；
- 没有 Controller 后，长研究可能更早结束；
- 长统一 Prompt 也可能产生清单化行为。

这些风险必须通过真实任务观察，而不是预先用更多架构补丁消灭。只有重复失败才授权增加窄机制。

## 10. 核心设计句

> 一个普通 Codex Chat 在极短项目宪法和统一数学建模 Prompt 下，自主使用原生联网、工具、计算、文件与委派能力，直接创造、检验、修订和交付数学模型；系统不在模型之外重复实现研究策略，只保留用户权力、证据边界和真实工件。
